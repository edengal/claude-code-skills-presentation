Recap

What Are Skills?

Skills are reusable markdown instruction files that teach Claude Code how to perform specific workflows. Think of them as executable playbooks — you write the steps once, and Claude follows them whenever triggered.

  • Stored as SKILL.md files with YAML frontmatter
  • Invoked manually via /skill-name or automatically when Claude detects a matching request
  • Follow the open Agent Skills standard (agentskills.io) — portable across AI tools
  • Live in .claude/skills/ at the project, personal, or enterprise level
  • Edits take effect immediately — no restart needed
One command turns a 30-minute workflow into seconds. Just describe what you want — Claude picks the right skill automatically.

The /fix-gus Skill

1

Parse Input

Extracts W-number from a GUS Lightning URL, W-number, or raw record ID.

2

Fetch GUS Details

Queries GUS for subject, details, priority, and status. Presents summary for confirmation.

3

Implement & Build

Creates branch @W-XXXXXXXX-slug, codes the fix, runs mvn clean install.

4

PR & Update GUS

Commits with @W-XXXXXXXX prefix, opens PR via git-soma, optionally updates GUS status.

How to Create Your Own Skill

Terminal
# Step 1: Create the directory
mkdir -p .claude/skills/my-workflow

# Step 2: Write the SKILL.md
cat <<'EOF' > .claude/skills/my-workflow/SKILL.md
---
name: my-workflow
description: >
  Describe when this should trigger so Claude
  knows when to auto-invoke it.
---

## Step 1: Gather context
Read the relevant files...

## Step 2: Make changes
Apply the pattern...

## Step 3: Verify
Run tests with !`npm test`
EOF

# Step 3: Commit to share with team
git add .claude/skills/
git commit -m "Add my-workflow skill"

Sharing With Your Team

Project Skills (Recommended)

  • Commit .claude/skills/ to your repo
  • Every team member gets them on clone/pull
  • Version-controlled alongside the code
  • Review skills in PRs like any other code

Other Options

  • Personal: ~/.claude/skills/ for cross-project use
  • Enterprise: Admins push org-wide via managed settings
  • Precedence: Enterprise → Personal → Project → Plugin
Compare

Skills vs Hooks vs MCP Servers

Skills Hooks MCP Servers
What Markdown playbooks Shell scripts on events External tool APIs
Trigger /command or auto Lifecycle events Claude's decision
Control Claude follows instructions Deterministic, always runs Claude calls as needed
Use case Multi-step workflows Format-on-save, validation Slack, GitHub, GUS
Rule of thumb: Keep copy-pasting the same procedure? → Skill  |  Need something to always happen? → Hook  |  Need external services? → MCP Server
Guidelines

Best Practices

Seven patterns for writing effective skills.

  • Clear descriptions — Claude uses the description field to decide when to auto-invoke
  • disable-model-invocation: true — for anything with side effects (deploys, deletions)
  • Keep SKILL.md under 500 lines — move reference docs to separate files and link them
  • Pre-approve tools with allowed-tools to reduce permission prompts
  • Use arguments for reusable skills: /fix-issue $0 where $0 is the issue number
  • Use paths to limit skills to relevant file types: paths: "**/*.go"
  • Test incrementally — edits to skills take effect immediately, no restart needed
